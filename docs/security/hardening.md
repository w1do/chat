# Hardening

Статус: implemented

Что уже сделано в продукте и что обязан сделать тот, кто разворачивает.

## В продукте

- API отвечает JSON всегда, включая исключения; единый envelope с `code`,
  `message`, `details`, `trace_id` — стектрейсы наружу не уходят.
- SPA-аутентификация на cookie Sanctum: `httpOnly`, `secure`, `SameSite`,
  CSRF-токен обязателен для мутаций (ADR-005).
- CORS и trusted proxies — явные allowlist из окружения, wildcard запрещён.
- Reverb в production принимает только перечисленные origin; внутренний порт
  наружу не публикуется, termination делает reverse proxy.
- Rate limiting: вход, регистрация, отправка сообщений, приглашения и AI.
- Все модели с `$fillable`; входные данные только через `validated()`.
- Пользовательский текст санитизируется и рендерится как текст, не как HTML.
- Контейнеры не root, образы закреплены по версиям, health checks у всех
  сервисов.
- `preventLazyLoading` вне production; тесты на утечку identity между
  запросами одного Octane worker.

## На стороне установки

1. **TLS обязателен.** Caddy в комплекте получает сертификат автоматически;
   при своём прокси проверьте, что заголовки `X-Forwarded-*` доверены только
   ему (`TRUSTED_PROXIES`).
2. **Секреты** — только через `.env` или менеджер секретов, файл `.env` с
   правами `600`, не в git. `APP_KEY`, `DB_PASSWORD`, `REDIS_PASSWORD`,
   `REVERB_APP_SECRET`, `TYPESENSE_API_KEY` — свои, не из примера.
3. **Порты.** Наружу только 80/443. PostgreSQL, Redis, Typesense и Reverb
   остаются во внутренней сети Compose.
4. **Пользователь БД** — с правами только на свою базу, без `SUPERUSER`.
5. **Резервные копии** проверяйте восстановлением, а не наличием файла
   (`docs/operations/backup-restore.md`).
6. **Обновления** — по upgrade notes релиза; `docker compose pull` с
   закреплёнными версиями, не `latest`.
7. **Администраторы.** Назначайте `chat:grant-admin` точечно; Horizon
   dashboard доступен только им.
8. **Пароли.** Минимальная длина по умолчанию — один символ (семейный чат).
   Если установка публичная или в комнатах есть чувствительное, поднимите
   `PASSWORD_MIN_LENGTH` в `.env` и перезапустите стек: значение уезжает и на
   сервер, и в интерфейс через `/config.json`, поэтому форма требует ровно то
   же число и называет его в подсказке. Пересобирать образ не нужно.
9. **Частота попыток входа и регистрации.** По умолчанию 5 входов, 10
   регистраций и 5 восстановлений пароля в минуту с адреса. Значения задаются
   окружением — `AUTH_LOGIN_PER_MINUTE`, `AUTH_REGISTER_PER_MINUTE`,
   `AUTH_PASSWORD_RESET_PER_MINUTE`. Понижайте их для публичной установки;
   поднимать имеет смысл только там, где за одним адресом сидит много людей
   (офис, NAT) — иначе вы снимаете защиту от перебора.
10. **Ссылки-приглашения.** У кого ссылка, тот войдёт в комнату: отправляйте их
   адресно и отзывайте, когда они сделали своё дело.
11. **AI выключен по умолчанию.** Включая его, вы соглашаетесь отправлять
   черновики внешнему поставщику — предупредите пользователей.

## Проверки

- `./tools/chat ci` — статический анализ, тесты, границы, контракты;
- `./tools/chat compose config` — валидность профилей;
- `./tools/chat smoke runtime` — готовность зависимостей после установки.
