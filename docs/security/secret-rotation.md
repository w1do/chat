# Ротация секретов

Статус: implemented

Все секреты живут в `.env` установки. Ротация — плановая (раз в год) или
немедленная при подозрении на утечку.

## Порядок

| Секрет | Как сменить | Последствие |
|---|---|---|
| `APP_KEY` | `php artisan key:generate --force` | зашифрованные значения (сохранённые токены) станут нечитаемыми — перед сменой сбросьте их; сессии и cookie инвалидируются, все входят заново |
| `DB_PASSWORD` | сменить в PostgreSQL (`ALTER ROLE … PASSWORD`), затем в `.env` | требуется перезапуск `api`, `worker`, `scheduler`, `reverb` |
| `REDIS_PASSWORD` | сменить в `redis-server --requirepass` и в `.env` | кэш, очереди и присутствие переподключаются; очереди в момент смены лучше остановить |
| `REVERB_APP_KEY` / `REVERB_APP_SECRET` | новые значения в `.env`, пересобрать конфигурацию web | все WebSocket-клиенты переподключаются; SPA получает ключ из `config.json`, обновление страницы обязательно |
| `TYPESENSE_API_KEY` | перезапустить typesense с новым ключом, обновить `.env` | после смены выполните `chat:search-reindex --fresh` |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | `php artisan chat:push-keys`, вписать новую пару | все подписки устройств перестают работать: людям нужно выключить и снова включить push в настройках |
| `AI_API_KEY` | отозвать у поставщика, вписать новый | помощник недоступен до обновления; чат работает |
| SMTP-пароль | сменить у провайдера и в `.env` | письма в очереди повторятся автоматически |

## После любой ротации

```bash
docker compose --env-file .env -f compose.prod.yaml up -d
./tools/chat deploy reload
./tools/chat smoke runtime
```

## При подозрении на компрометацию

1. Смените затронутый секрет **и** `APP_KEY` (инвалидирует сессии).
2. Снимите резервную копию БД до любых изменений — она понадобится для
   разбора.
3. Проверьте `audit_logs`: кто и что менял, когда появились администраторы.
4. Сообщите пользователям, если могли пострадать их данные.
