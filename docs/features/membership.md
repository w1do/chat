# Членство в комнатах

Статус: verified (E2E `./tools/chat e2e messaging`, `./tools/chat e2e membership`)

## Роли и права

| Действие | owner | admin | member | guest |
|---|---|---|---|---|
| Просмотр участников | ✓ | ✓ | ✓ | публичные — ✓ |
| Приглашение | ✓ | ✓ | — | — |
| Поиск людей по нику | ✓ | ✓ | — | — |
| Вступление (public) | — (уже член) | — | — | ✓ |
| Выход | — (нужна передача владения) | ✓ | ✓ | — |
| Исключение участника | любого, кроме себя | только роль member | — | — |
| Смена ролей admin/member | ✓ | — | — | — |

Роль owner не назначается сменой роли; ровно один owner на комнату
закреплён частичным уникальным индексом БД.

Админ не исключает ни владельца, ни другого админа. Владелец не исключает
собственную запись: иначе комната осталась бы без владельца — для этого нужна
передача владения, а не исключение.

## Приглашение по нику

Человека зовут, зная только его ник: в форме приглашения вводится `@ник`
(собака необязательна), поиск показывает найденных с их именами, и нужный
добавляется нажатием. Внутренний идентификатор пользователя вводить не нужно
и нигде не показывается.

Правила поиска: минимум два символа, совпадение с начала ника без учёта
регистра, не больше десяти человек в ответе. Ответ содержит только ник и
отображаемое имя, спрашивать может лишь тот, кто вправе приглашать в эту
комнату, а частота запросов ограничена так же, как у приглашений — список
людей установки не становится открытым справочником.

Уже состоящие в комнате помечены в результатах и повторно не приглашаются.
Если не нашли никого — интерфейс предлагает позвать человека ссылкой
(`docs/features/invite-links.md`).

## Что остаётся после исключения

Исключение убирает только участие. Сообщения исключённого остаются в комнате,
а сам факт исключения попадает в историю комнаты системной записью
(`member.removed`), как вступление и выход.

Исключённый узнаёт об этом сразу: открытая комната закрывается с сообщением,
что он больше в ней не состоит, и человек возвращается к списку комнат;
закрытая комната из списка пропадает. Дальше он для комнаты — посторонний:
не читает её и не пишет в неё.

Блокировки в продукте нет: исключённый может вернуться по действующей
ссылке-приглашению или вступить снова, если комната публичная. Отозвать
ссылку владелец может отдельно.

## Реализация

- Backend: `RoomMember`, `MembershipPolicy` (включая `remove`), команды
  Invite/Join/Leave/RemoveMember/ChangeMemberRole (конфликты — 409, гонки —
  `lockForUpdate` в транзакции), запрос `SearchMemberCandidates`,
  scoped route bindings (участник чужой комнаты → 404).
- Frontend: `InvitePanel` и `MemberRow` в `@vendor/chat`; `RoomSettingsPage`
  в `chat-web`.

## API

`GET/POST /rooms/{room}/members`, `POST/DELETE /rooms/{room}/members/me`,
`PATCH/DELETE /rooms/{room}/members/{member}`,
`GET /rooms/{room}/member-candidates` — см. OpenAPI dist.

Изменения состава расходятся событием `room.member_changed.v1` с
`action: invited | joined | left | removed | role_changed`.

## Edge cases

- Повторное приглашение/вступление → 409/403; не-член → 403; чужой member → 404.
- Исключение владельца или админа админом → 403; своя запись у владельца → 403.
- Исключение постороннему не показывает комнату вовсе → 404.
- Запрос поиска короче двух символов не ищет ничего и ошибкой не является.

## Критерии приёмки / проверки

- `./tools/chat test chat`, `./tools/chat test api`, `./tools/chat web test chat` — проходят.

Запуск E2E: `./tools/chat e2e messaging` — вступление в открытую комнату и доступ
к переписке после него; `./tools/chat e2e membership` — приглашение по нику и
исключение участника, читавшего комнату.

## Приглашение по ссылке

К вступлению в открытую комнату и приглашению по нику добавился третий путь —
ссылка: участник нажимает «Пригласить», человек открывает ссылку и оказывается
в комнате, даже если аккаунта у него ещё не было. Подробности и границы —
`docs/features/invite-links.md`.
