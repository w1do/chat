# Приглашение по ссылке

Статус: implemented

## Как это выглядит

Участник комнаты нажимает **«Пригласить»** в её шапке — и в буфере обмена
оказывается готовый текст:

```
Привет! Приглашаю тебя в чат «Семья».
Ссылка: https://chat.example.ru/invite/<токен>
Ссылка действует до 1 сентября.
```

Если буфер недоступен (чат открыт по http), приложение показывает саму
ссылку — приглашение не пропадает молча.

Человек открывает ссылку, видит, куда и кто его зовёт, называет своё имя — и
оказывается в комнате. Аккаунт создаётся сам: логин и пароль генерируются,
поменять их можно в настройках. Уже вошедший пользователь по той же ссылке
просто вступает в комнату.

## Границы

- Ссылку создаёт **любой участник** комнаты; для архивной комнаты — нельзя.
- Живёт **7 дней** (`INVITE_LIFETIME_DAYS`), работает **многократно**.
- Ведёт **строго в свою комнату**: доступа к другим приватным комнатам не даёт.
- Приглашённый получает роль обычного участника.
- Повторный переход по ссылке безопасен: второй записи об участии не будет.
- Отзывается в один шаг — после этого перестаёт работать немедленно.

## Что важно понимать про безопасность

**У кого ссылка — тот войдёт.** Она попадёт в чужую переписку и останется там,
поэтому обращайтесь с ней как с приглашением в закрытый чат: отправляйте тем,
кого действительно зовёте, и отзывайте, когда она сделала своё дело.

Токен в базе не хранится — только его SHA-256: утечка дампа не отдаёт рабочих
ссылок. Отозванная, просроченная и несуществующая ссылка отвечают одинаково,
чтобы перебирающему нечего было узнать.

Создание ссылок и вступление по ним ограничены по частоте
(`INVITE_CREATE_PER_MINUTE`, `INVITE_ACCEPT_PER_MINUTE`).

## Аккаунт по приглашению

Логин собирается из имени с коротким случайным суффиксом (`nadia-7f3k`),
пароль генерируется и **нигде не показывается** — он существует, чтобы у
аккаунта был валидный хэш. Пока человек не задал свой пароль, настройки
показывают подсказку: вход держится на этом устройстве.

Как только он задаст пароль, аккаунт ничем не отличается от обычного.

## API

`POST /rooms/{room}/invites`, `DELETE /invites/{invite}`,
`GET /invites/{token}`, `POST /invites/{token}/accept` — см. OpenAPI dist.

## Проверки

- `./tools/chat test chat` — создание, срок, отзыв, повторный переход,
  несколько гостей по одной ссылке;
- `./tools/chat test api tests/Integration/InviteFlowTest.php` — путь целиком:
  создание, гость без аккаунта, вошедший пользователь, мёртвая ссылка и откат;
- `./tools/chat web test` — кнопка, текст приглашения, экран перехода;
- `./tools/chat e2e invite` — два браузера: участник зовёт, гость называет имя,
  пишет в комнату и видит подсказку про пароль.
