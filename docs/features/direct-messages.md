# Личная переписка

Статус: implemented

## Как это выглядит

В списке переписок под комнатами есть **«Новый диалог»**. Человек вводит `@ник`
собеседника — поиск тот же, что у приглашения в комнату, — нажимает найденного
и сразу оказывается в пустой личной переписке.

Диалог живёт в общем списке рядом с комнатами: комната подписана названием,
диалог — именем собеседника и его ником. Непрочитанное считается одинаково.

В шапке диалога — имя собеседника и `@ник`. Комнатных действий там нет:
переименовать, позвать третьего, посмотреть участников нельзя.

## Границы

- Переписка возможна **с любым человеком этой установки**, найденным по нику;
  с самим собой — нельзя.
- Между парой людей **ровно один** диалог: повторное начало открывает прежний
  вместе со всей историей, порядок людей значения не имеет.
- Пока в диалоге ничего не написано, у собеседника он в списке **не появляется**.
- У диалога нет названия, описания, ролей и приглашений. Переименование,
  архивирование, удаление, публикация и добавление третьего человека
  отклоняются — и в интерфейсе, и запросом напрямую.
- Среди комнат, к которым можно присоединиться, чужих диалогов нет; для
  постороннего такой переписки не существует.
- Выйти из диалога нельзя: уходить из личной переписки некуда.

## Что в диалоге работает как в комнате

Отправка, редактирование и удаление сообщений, ответы, реакции, упоминания,
пагинация истории, набор текста и присутствие, real-time доставка, уведомления,
поиск по истории и помощник — всё то же и с теми же ограничениями. События
приходят прежними схемами (`message.created.v1` и остальные), приватный канал
авторизуется по участию.

## Скрытие

Диалог можно **убрать из своего списка** — с одним подтверждением, чтобы
случайное касание не спрятало переписку. Скрытие действует только на того, кто
скрыл: у собеседника диалог остаётся, история сохраняется целиком.

Новое сообщение возвращает диалог в список вместе со всей перепиской.
События приходят только по перепискам из списка, поэтому список сам
перечитывается с небольшим периодом — скрытый диалог возвращается без
перезагрузки страницы.

## Уведомления

Уведомление о личном сообщении называет **отправителя**, а не комнату, и ведёт
в этот диалог. Остальные правила не меняются: инициатор себя не уведомляет,
активный в переписке получатель уведомления не получает, предпочтения каналов
соблюдаются. См. [notifications.md](notifications.md).

## API

`POST /direct-conversations` — начать или открыть диалог,
`POST /direct-conversations/{room}/hide` — скрыть у себя,
`GET /direct-conversation-candidates` — поиск собеседника по нику.
Представление переписки сообщает вид (`kind`) и собеседника
(`counterpart`) — см. OpenAPI dist.

## Проверки

- `./tools/chat test chat` — пара без порядка, один диалог на двоих, запрет
  диалога с собой, скрытие и возврат, отказ комнатных действий;
- `./tools/chat test api tests/Feature/DirectConversationsTest.php` — начало,
  повтор, скрытие, посторонний, представление с собеседником;
- `./tools/chat web test chat` — смешанный список, начало по нику, шапка
  диалога, скрытие с подтверждением и возврат;
- `./tools/chat e2e direct-messages` — два браузера: диалог по нику, обмен в
  реальном времени, скрытие и возврат с новым сообщением.
