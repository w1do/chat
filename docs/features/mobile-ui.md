# Мобильный интерфейс

Статус: implemented

Продуктовый интерфейс собран из прототипа мобильного чата (каталог `chat/`
в корне — исходная вёрстка) и связан с реальным API.

## Раскладка (STRUCTURE.md §4)

- `packages/frontend/ui` — дизайн-система без продуктовой логики: токены
  светлой/тёмной темы (`styles/tokens.ts`), анимации и safe-area
  (`styles/global.css`), примитивы `Avatar`/`Dots`/`Toggle`/`Segmented`/
  `Sheet`/`Row`/`Group`/`Toast`, хуки `useKeyboardInsets`, `useElementHeight`,
  `useTheme`. `Avatar` показывает загруженную картинку, а буква имени с
  оттенком остаётся запасным видом — при её отсутствии, во время подготовки
  и при неудачной загрузке (`docs/features/profile-images.md`).
- `packages/frontend/chat` — экраны: `RoomsScreen` (список комнат, счётчики
  непрочитанного, создание комнаты), `ChatScreen` (лента с группировкой по
  автору, дни, ответы, реакции, упоминания, набор текста, состояние
  соединения), `MagicSheet` (помощник).
- `apps/chat-web` — оболочка: вкладки «Чаты»/«Настройки», слой переписки,
  экран участников, локальные настройки (тема, размер текста, анимации,
  «печатает», Enter отправляет).

## Соответствие домену

Прототип описывал «семейный» чат с ролями owner/parent/teen/child/guest и
доступом по ролям. Бэкенд этого не знает, поэтому интерфейс использует
реальную модель:

| Прототип | Реализация |
|---|---|
| роли семьи | роли комнаты: `owner`, `admin`, `member` |
| readRoles/writeRoles | `visibility` (public/private) + членство |
| аватар и цвет участника | выводятся из идентификатора (`voiceHue`, инициал) |
| эмодзи комнаты | выводится из названия (`roomEmoji`) |
| магическая кнопка | `MagicSheet`; активна только при `ai.enabled` в `/config.json` |
| вход | логин и пароль без почты; почта — в настройках (ADR-005) |
| SystemMessage | `kind: system` в общей ленте; текст формулирует клиент |
| события присутствия | «печатает», presence-точки, конфетти при вступлении |
| статусы доставки | «отправляется» (оптимистично) / «отправлено» (сохранено) |
| вложения, голос | не входят в MVP |

## Правило оформления

Прототип — единственный источник визуального языка (design decision 1a):
новые элементы добавляются примитивами в `packages/frontend/ui`, а не
локальными стилями. В `apps/chat-web` нет ни блоков `<style>`, ни цветовых
литералов — только токены темы; это проверяется при аудите экранов.

## Что добавлено в API ради интерфейса

- `unread_count` в `GET /rooms` — счётчик непрочитанного по комнатам, где
  пользователь состоит (для чужих комнат — `null`);
- `POST /rooms/{room}/read` — отметка прочтения (не двигается назад);
- `PATCH /me/email` и `PATCH /me/password` — почта и пароль из настроек.

## Проверки

- `./tools/chat web test chat` (22 теста) и `./tools/chat web test ui` (4);
- `./tools/chat test api tests/Feature/RoomsTest.php` — счётчики и отметка;
- `./tools/chat e2e realtime` — два пользователя в реальном стеке.

## Действия над сообщением

Постоянных кнопок у сообщений нет — они загромождали ленту. Действия живут на
жестах, и каждое дублируется в меню, чтобы ничего не потерялось:

| Действие | Телефон | Компьютер | Клавиатура |
|---|---|---|---|
| Ответить | свайп влево | меню правым кликом | `Enter` → «Ответить» |
| Быстрая реакция `❤️` | двойное касание | двойной клик | меню → палитра |
| Реакция, копирование, удаление | долгое нажатие | правый клик | `Enter` на сообщении |

Свайп засчитывается после 56 px и отменяется, если палец ушёл по вертикали
больше чем на 24 px — вертикальная прокрутка остаётся главной. Повторное
двойное касание снимает свою реакцию. Удалённые сообщения жестов не принимают.

При первом входе в комнату один раз показывается подсказка о свайпе и долгом
нажатии; факт показа хранится локально в браузере.

## «Печатает»

Индикатор живёт в шапке комнаты и подменяет описание комнаты, поэтому лента не
дёргается. Перечисление сворачивается: «Алексей печатает…», «Алексей и Андрей
печатают…», «Алексей, Андрей, Надя и ещё 1 печатают…». Настройка «Показывать
печатает» отключает его целиком.

## Оболочка приложения

Приложение занимает ровно видимую область и **не прокручивается**: у документа
запрещены прокрутка и резиновый отскок. Двигается только содержимое.

Каждый экран построен на примитиве `Screen` из `@vendor/ui`: закреплённая
шапка, одна прокручиваемая середина, закреплённый низ (панель ввода или
навигация). Раскладка — grid `auto / minmax(0, 1fr) / auto`; `minmax(0, 1fr)`
здесь принципиален: без него середина не сжимается ниже своего содержимого и
распирает экран — именно так и появлялась прокрутка всей страницы вместо
прокрутки ленты.

Следствие, принятое сознательно: на Android пропадает системное «потянуть
вниз, чтобы обновить». Для приложения-оболочки это ожидаемо; обновить страницу
можно средствами браузера.

## Масштаб и жесты

Жестом приложение не масштабируется: ни щипок двумя пальцами, ни двойной тап
не меняют масштаб — ни в ленте, ни на любом другом экране. Закрыто это двумя
средствами, и оба обязательны, потому что закрывают разные браузеры:

- `touch-action: pan-x pan-y` на `html`, `body` и `#root` в
  `apps/chat-web/src/styles/index.css`. Именно `pan-x pan-y`, а не
  `manipulation`: тот раскрывается в `pan-x pan-y pinch-zoom` и щипок как раз
  разрешает, убирая только двойной тап. Правило общее для всех экранов, и
  повторять его на картинках и пузырях не нужно — жест запрещён уже предком;
- подавление `gesturestart`/`gesturechange`/`gestureend` с `passive: false`
  (`apps/chat-web/src/app/zoom-gestures.ts`, ставится один раз при запуске).
  Это нестандартные события, которыми iOS Safari сообщает о щипке:
  `touch-action` для масштаба страницы он не слушает. В остальных браузерах
  события не приходят вовсе, поэтому ветвления по user-agent нет.
  `passive: false` обязателен: у пассивного слушателя `preventDefault` не
  работает.

Гасить `touchend` ради двойного тапа нельзя: вместе с зумом отменяется и
быстрая реакция двойным касанием — жест просто не доходит до приложения.

Само увеличение при этом остаётся доступным. `<meta viewport>` намеренно не
содержит ни `user-scalable=no`, ни `maximum-scale=1`: они запрещают не жест, а
саму возможность увеличить текст, и нарушают WCAG 2.2 AA (критерий 1.4.4).
Масштаб страницы из меню браузера, системное принудительное увеличение и
размер текста в настройках приложения работают как прежде. Настольные браузеры
не затронуты: `Ctrl` с колесом и `Ctrl` с «+/−» остаются.

Пока страница увеличена, приложение не принимает уменьшившуюся видимую область
за клавиатуру — см. следующий раздел.

## Клавиатура и безопасные зоны

Приложение занимает ровно видимую область (`visualViewport`) и компенсирует
прокрутку, которую iOS Safari делает сам при открытии клавиатуры, — поэтому
шапка не уезжает вверх.

Уменьшение вьюпорта считается клавиатурой только начиная со 120 px: на iOS
layout-вьюпорт выше визуального из-за адресной строки, и без порога приложение
считало бы клавиатуру открытой всегда — а значит убирало бы нижний безопасный
отступ, и панель ввода пряталась бы под системной чертой. В `<meta viewport>` добавлен
`interactive-widget=resizes-content`: где он поддержан, браузер уменьшает
вьюпорт вместо прокрутки. Нижний отступ добавляется только при закрытой
клавиатуре, иначе под панелью ввода оставалась бы пустая полоса.

Нижний отступ закреплённого низа — это только вырез устройства
(`env(safe-area-inset-bottom)`). Полосу браузера добавлять к нему нельзя:
оболочка уже задаёт себе высоту по видимой области, то есть полоса вычтена, и
вторая поправка на неё превращалась в пустоту под панелью ввода.

Здесь легко ошибиться дважды. Сначала кажется, что панель уходит под полосу
браузера, — на самом деле это выпавший из сборки файл стилей (см. ниже).
Потом кажется, что полосу надо прибавить отступом, — и появляется пустота.

### Масштаб не путается с клавиатурой

Увеличенная страница уменьшает видимую область и получает сдвиг ровно так же,
как открытая клавиатура. Поэтому `useKeyboardInsets` сверяется с
`visualViewport.scale`: пока масштаб заметно больше единицы (сравнение с
допуском — браузеры отдают дробные значения вроде `1.0000001`), клавиатура
считается нулевой, а сдвиг не применяется. Без этого панель ввода всплывала к
середине экрана, стоило свести пальцы. Браузеру, который `scale` не отдаёт,
ничего не выдумывается: поведение остаётся прежним.

Высота при увеличении берётся не меньше `window.innerHeight`. Видимая область
увеличенной страницы — окошко, скользящее по layout-вьюпорту, а оболочка стоит
`position: fixed`, то есть меряется именно layout-вьюпортом: при двукратном
увеличении высота окошка дала бы половину страницы, пустоту под оболочкой и
панель ввода посреди экрана.

Ограничитель намеренно ограничен увеличением. Шире — «при любой закрытой
клавиатуре» — он срабатывал бы ровно там, где вредит: клавиатура считается
закрытой при недоборе меньше 120 px, то есть в случае адресной строки iOS,
и оболочка выросла бы до высоты окна, унеся панель ввода под панель браузера.
А устаревшую геометрию он не чинит вовсе: там недобор больше порога и
клавиатура считается открытой. Её чинит перемер по возврату.

### Возврат из фона

События изменения размера при разворачивании приложения могут не прийти
вовсе — и на экране остаются числа, снятые до сворачивания: панель ввода
посреди экрана, под ней полоса. Поэтому `useKeyboardInsets` перемеряет
геометрию по трём событиям возврата, и три их потому, что пути возврата дают
разное: разворачивание из фона — `visibilitychange` документа, восстановление
страницы из кеша навигации — `pageshow`, а открытие по нажатию на
пуш-уведомление (service worker наводит уже запущенное окно через
`client.navigate` + `client.focus`) на iPhone может не дать ни того ни
другого — там срабатывает `focus` окна.

Одного измерения мало: в момент разворачивания браузер ещё двигает системные
панели и убирает клавиатуру. За событием следует серия — сразу, после
отрисовки кадра и ещё несколько раз с возрастающими паузами примерно до
секунды; побеждает последнее измерение. Серия не превращается в серию
рендеров: состояние обновляется, только если числа действительно изменились.

Под оболочкой закрашен фон темы: `html`/`body` красятся переменной
`--app-bg`, которую `useTheme` держит в согласии с текущей темой. Это не чинит
геометрию, а убирает самое заметное её проявление — постороннюю серую полосу
там, где оболочка почему-либо не покрыла экран.

### Панель ввода на узком экране

Панель ввода занимает всю ширину экрана и не превышает её ни при каком
черновике. Отвечают за это три правила, и все три обязательны:

- строка ввода — `min-w-0`, `max-w-full` и `overflow-hidden`. Без `min-w-0`
  гибкие дети не сжимаются ниже собственной ширины, а собственная ширина
  `textarea` берётся из `cols` и на телефоне в 360 px не оставляет места
  кнопкам — именно так эмодзи, помощник и отправка уезжали за правый край;
- само поле — `flex-1 min-w-0`: ширину отдаёт оно, а не кнопки;
- эмодзи, помощник и отправка — одна группа `shrink-0` с общим шагом.

Панель закреплена у нижнего края (`sticky bottom-0`) и остаётся там, даже
если однажды окажется внутри прокручиваемой области, а не закреплённым низом
`Screen`. Нижний отступ — только вырез устройства и только при закрытой
клавиатуре (см. выше).

Кнопка отправки уезжает вправо отрицательным полем, когда отправлять нечего.
Поле анимируется вместе с ней: строка обрезана по краю, и без плавности
кнопка пропадала бы скачком, а не уходила за край.

### Приглашение на телефоне

До ширины 640 px приглашение участников открывается листом почти во весь
экран, а не карточкой в потоке страницы: на телефоне карточка оказывалась
внизу длинного экрана, а открытая клавиатура прятала и поле поиска, и кнопки.

В листе закреплены оба края. Поле поиска липнет к верху области прокрутки,
кнопки «Пригласить ссылкой» и «Готово» лежат в панели действий `Sheet` —
она вне прокрутки, поэтому длинный список найденных не уносит их с собой.
Нижний безопасный отступ при этом переходит от прокрутки к панели действий:
иначе кнопки легли бы на системную черту.

Сам экран комнаты тоже занимает ровно видимую область и компенсирует
прокрутку iOS Safari — так же, как экран переписки. Без этого поле поиска
приглашения оказывалось под клавиатурой.

Тач-таргеты приглашения — не меньше 44×44 pt (WCAG 2.2 AA): поле поиска,
строки найденных, обе кнопки панели действий. Кнопка закрытия листа осталась
кружком в 30 px, но нажимается на 44×44 — лишнее снимает отрицательное поле,
поэтому раскладка листов не съехала.

От 641 px приглашение остаётся карточкой в потоке страницы: места хватает,
и лист там был бы лишним.

### Контраст и видимый фокус

Вторичный текст — подписи полей, ники, подсказки, описания комнат — держит
4.5:1 (WCAG 2.2 AA) на всех трёх фонах темы. Проверять его нужно по худшему
фону: на `surfaceAlt` запаса меньше всего, и именно там прежний `muted`
проваливался до 3.12:1 в светлой теме. Токен затемнён в обеих темах
(`#6A6974` и `#9695A1`), порог закреплён тестом `packages/frontend/ui/tests/
contrast.test.tsx` — он считает контраст по формуле WCAG и падает, если
подобрать «покрасивее» ценой читаемости.

Выключенный значок помощника (`faint` на `surfaceAlt`) остаётся ниже порога
осознанно: WCAG 1.4.11 не предъявляет требований к неактивным элементам, а
приглушённость и есть сообщение «AI выключен».

Поле ввода сообщения гасит системную рамку фокуса, поэтому носит `field-focus`
и рисует свою: без неё у переходящего табуляцией не оставалось никакого
признака, что он уже в поле.

### Стили обязаны доезжать до сборки

`@import` дизайн-системы стоит первым в `apps/chat-web/src/styles/index.css`,
до `@tailwind`. Порядок не косметический: `@import` после других правил
сборщик выбрасывает целиком — вместе с ним пропадали `.safe-bottom`,
`.no-select`, `.tap` и все анимации, а приложение выглядело так, будто
мобильные починки не сделаны. Единственным следом было предупреждение сборки
«@import must precede all other statements».

### Долгое нажатие

Долгое нажатие открывает меню действий и не запускает системное выделение:
класс `.no-select` в `packages/frontend/ui/src/styles/global.css` пишет
`user-select`, `-webkit-user-select` и `-webkit-touch-callout: none` (одного
стандартного свойства мобильному Safari мало) и висит и на пузыре сообщения, и
на слое листа-меню. Поля ввода и поиск из запрета исключены явным правилом,
копирование остаётся действием меню «Копировать текст».

### Показ пароля

Кнопка показа внутри поля пароля гасит `mousedown`, а не только возвращает
фокус: программный возврат фокуса на iOS клавиатуру не удерживает, и она
схлопывается. Тип поля меняется императивно, вместе с синхронным возвратом
каретки — асинхронное восстановление догоняет человека, когда он уже печатает,
и перемешивает ввод.

Полям пароля выключены автозаглавные, автокоррекция и проверка орфографии:
на открытом поле iOS иначе правит пароль сам. Подробности поведения —
`docs/features/authentication.md`.

### Проверка на устройствах

Проверка на настоящем устройстве (iPhone, Safari; Android, Chrome) —
обязательный шаг перед релизом: долгое нажатие без синей подсветки и без
системного меню, «Копировать текст», панель ввода целиком видна при закрытой и
открытой клавиатуре, с системной полосой навигации по полям, после поворота и
при скрытии адресной строки. Для показа пароля: клавиатура не схлопывается при
нажатии кнопки, набранное и позиция курсора сохраняются, автозамена не
срабатывает, длинный открытый пароль не уезжает под кнопку, а после отправки
браузер предлагает сохранить пароль.

Отдельно проверяется возврат по уведомлению — эмуляцией он не
воспроизводится: свернуть приложение с открытой клавиатурой, открыть его
нажатием на пуш-уведомление и убедиться, что оболочка занимает экран целиком,
а под панелью ввода нет полосы. Там же проверяется запрет жеста: щипок и
двойной тап не меняют масштаб, а увеличение из меню браузера и системная
настройка принудительного увеличения продолжают работать.

## Проверки

`./tools/chat web test chat` — жесты, меню действий, лента с аватарами и
разделителями дня, «печатает» в шапке, подсказка, структура оболочки (одна
область прокрутки, края вне её), ограничения ширины панели ввода и лист
приглашения (прокрутка списка при закреплённых действиях, тач-таргеты);
`./tools/chat web test` — хук `useKeyboardInsets` (клавиатура, масштаб,
перемер по возврату из фона и снятие слушателей), подавление жестов
масштабирования, фон документа по теме и экран входа;
`./tools/chat e2e mobile-composer` — на экране 360×780 панель ввода, её кнопки
и лист приглашения целиком помещаются в экран, горизонтальной прокрутки нет, а
уменьшение вьюпорта под клавиатуру не прячет ни поле ввода, ни кнопки и не
теряет набранное; `./tools/chat e2e mobile-zoom` — двойной тап по ленте не
меняет масштаб, а после ухода страницы в фон и возврата панель ввода остаётся
у нижнего края; `./tools/chat e2e critical` — сценарии в браузере, включая
проверку того, что после прокрутки ленты `window.scrollY` остаётся нулём, а
документ не переполняется.
