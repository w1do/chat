# Уведомления

Статус: verified (E2E `./tools/chat e2e messaging`)

## Главное правило

**Уведомление не создаётся тому, кто сейчас в этой комнате.** Активность
берётся из Redis-реестра присутствия пакета `chat` через контракт
`ActivityInspector`; связывает пакеты приложение
(`app/Providers/PackageWiringProvider.php`), сами пакеты друг о друге не знают.

Инициатор события не уведомляется никогда — в том числе если упомянул себя.

## Категории и каналы

| Категория | Что это | Лента | Почта | Push | Очередь |
|---|---|---|---|---|---|
| `message` | новое сообщение в комнате | вкл | выкл | вкл | `notifications-bulk` |
| `mention` | вас упомянули | вкл | вкл | вкл | `notifications` |
| `room_invite` | вас добавили в комнату | вкл | вкл | вкл | `notifications` |
| `security` | безопасность и администрирование | **всегда вкл** | вкл | вкл | `notifications-critical` |

Пользователь меняет каналы в настройках («Каналы уведомлений»). Ленту для
категории «Безопасность» отключить нельзя — попытка возвращает 422.

## Группировка

Повторяющиеся события одной комнаты внутри окна обновляют одну запись и
увеличивают `group_count` вместо создания новых. Окна: сообщения — 15 минут,
упоминания — 5 минут (`NOTIFY_GROUP_*_SECONDS`).

## Доставка

Медленные каналы уходят в очередь: `DeliverNotificationJob` идемпотентен
(уникальный ключ «получатель + канал + повод»), имеет `tries`, `backoff`,
`timeout` и `failed()`. Провал письма пишется в журнал и **не влияет** ни на
сохранённое сообщение, ни на real-time доставку. `SendDigestJob` шлёт сводку
непрочитанного одним письмом. Аккаунтам без почты (вход по логину, ADR-005)
письма не отправляются.

Цепочка таймаутов соблюдается: job timeout (30 с) < Horizon supervisor timeout
< queue `retry_after` (см. `docs/operations/supervisor.md`).

## Push-уведомления на устройство

Push доходят, когда чат закрыт: сервер отправляет их через Web Push с ключами
VAPID напрямую в push-сервис браузера — без Firebase и любого внешнего
control plane.

Правила те же, что и у остальных каналов: не тому, кто сейчас в комнате, не
инициатору, с группировкой шумных комнат. В уведомление идёт комната, автор и
короткий фрагмент — ровно то, что человек и так увидит в ленте; длинный текст
обрезается. **Это видно на экране блокировки** — учитывайте при обсуждении
чувствительного.

Включение на сервере:

```bash
docker compose exec api php artisan chat:push-keys   # ключи VAPID
# впишите VAPID_* в .env и перезапустите стек
```

Без ключей push просто выключены: канал не предлагается, остальные работают.

Пользователь управляет push одним тумблером в настройках: включение
запрашивает разрешение браузера и подписывает устройство, выключение снимает
подписку — системные уведомления не приходят вовсе. Лента и письма при этом
продолжают работать по предпочтениям категорий.

Устройства, которые push-сервис объявил недействительными (404/410),
удаляются автоматически. Прочие ошибки уходят в повтор очереди и **не влияют**
на отправку сообщения.

На iPhone push работают только у установленного приложения — см.
`docs/features/installable-app.md`.

## API

`GET /notifications`, `POST /notifications/read`,
`GET|PATCH /notification-preferences`, `POST|DELETE /push-subscriptions` —
см. OpenAPI dist.

## Интерфейс

- Колокольчик с точкой непрочитанного в шапке списка чатов.
- Экран «Уведомления»: лента с категориями, счётчиком свёрнутых событий
  (`×4`), переходом в комнату и кнопкой «Отметить всё прочитанным»;
  состояния loading/empty/error.
- Настройки → «Каналы уведомлений»: переключатели по категориям и каналам,
  заблокированные строки объясняют, почему их нельзя выключить.
