# ADR-003: Laravel Reverb и модель real-time доставки

- Статус: accepted
- Дата: 2026-08-24

## Контекст

Чату нужна доставка событий в реальном времени внутри self-hosted стека без
внешних SaaS. Инструкция фиксирует Reverb как единственный штатный
WebSocket-сервер и требует версионирования событий, авторизации приватных
каналов и отправки только после commit.

## Решение

- **Транспорт**: Laravel Reverb (pusher-совместимый протокол) как отдельный
  процесс стека; TLS/WebSocket termination — на reverse proxy (ADR-007),
  внутренний порт наружу не публикуется, `REVERB_ALLOWED_ORIGINS` — явный
  allowlist.
- **Разделение ролей**: `Domain/Events/*` — факты внутри транзакции;
  `Infrastructure/Broadcasting/*V1` — версионированный транспорт с урезанным
  payload по схеме из `packages/contracts`. Мост — слушатели
  `BroadcastsDomainEvents`, регистрируемые провайдером пакета.
- **После commit**: все broadcast-классы реализуют `ShouldDispatchAfterCommit`;
  тест доказывает отсутствие рассылки при rollback.
- **Каналы**: приватный `room.{id}` (участники), presence
  `room.{id}.presence` (typing/присутствие), приватный `user.{id}`
  (уведомления, этап 8). Авторизация — `apps/chat-api/routes/channels.php`;
  маршрут `/broadcasting/auth` проходит session-стек (`web` + `auth:sanctum`),
  иначе cookie не читается.
- **Клиент**: WebSocket — не источник истины. `packages/frontend/chat`
  применяет события к кэшу TanStack Query, а после reconnect выполняет
  HTTP-ресинхронизацию (`resyncRoom`), поэтому пропущенные события
  восстанавливаются.
- **Очередь**: broadcast'ы уходят через очередь (Horizon/worker), что снимает
  задержку с HTTP-ответа.

## Альтернативы

- **Soketi / внешний Pusher** — отвергнуто: дополнительный компонент или
  внешняя зависимость в self-hosted поставке.
- **SSE/long-polling** — отвергнуто: нужен двунаправленный канал (typing,
  presence).
- **Reverb presence-каналы как источник истины о присутствии** — отвергнуто:
  корректность уведомлений привязалась бы к жизненному циклу сокета; истина —
  Redis-реестр с TTL.
- **Синхронная рассылка без очереди** — отвергнуто: внешний вызов в цикле
  HTTP-запроса.

## Последствия

- Горизонтальное масштабирование Reverb требует общего Redis pub/sub и
  балансировщика (проверяется нагрузочным тестом, этап 12).
- Изменение payload события = новая версия схемы (`*.v2`), старая живёт до
  снятия потребителей.
- В стеке обязателен worker: без него broadcast-задания не выполняются.

## Критерии пересмотра

- Появление требования к межсерверной федерации или к доставке вне браузера.
- Ограничения Reverb под нагрузкой, выявленные нагрузочным тестом.
