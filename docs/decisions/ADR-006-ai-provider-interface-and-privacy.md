# ADR-006: Интерфейс AI-провайдера и приватность

- Статус: accepted
- Дата: 2026-08-25

## Контекст

Чат помогает править черновик текста. Обработка выполняется внешним сервисом,
поэтому нужны: замена поставщика без переписывания домена, жёсткие границы того,
что уходит наружу, предсказуемая стоимость и работоспособный чат при отказе AI
(CLAUDE.md §9).

## Решение

- **Единственный порт** — `Vendor\Ai\Domain\Contracts\TextRevisionProvider`
  (`revise(DraftText, RevisionOperation, tone?, instruction?): RevisionResult`).
  Домен и Application не знают ни про HTTP, ни про формат поставщика.
- **Реализации**: `PolzaProvider` (Polza AI — OpenAI-совместимый
  `POST /chat/completions`, `Authorization: Bearer`, модель из конфигурации),
  `NullProvider` (по умолчанию и при отсутствии ключа — помощник молчит,
  чат работает), `FakeTextRevisionProvider` для тестов и CI.
- **Приватность**: наружу уходит только присланный текст и системный промпт
  операции. История комнаты, участники, идентификаторы сообщений не передаются —
  это закреплено тестом на реальном HTTP-запросе.
- **Аудит без приватного содержимого**: в `ai_requests` пишутся операция,
  пользователь, поставщик, модель, статус, токены, стоимость в минимальных
  единицах, длина ввода, длительность и короткая причина отказа. Ни промпта,
  ни ответа, ни ключей; проверяется тестом.
- **Ограничения**: максимальная длина ввода проверяется до вызова поставщика;
  квоты на пользователя (в минуту и в час); таймаут; один повтор только для
  сетевого сбоя; circuit breaker размыкает цепь после череды отказов.
- **Результат — предложение**: ответ содержит исходный текст и вариант; замена
  черновика происходит только по явному действию пользователя, с возможностью
  вернуть свой текст. Интерфейс сообщает, что текст обработан внешним ИИ.
- **Выключатель**: `ai.enabled`. При выключенном помощнике endpoint отвечает
  503, кнопка в композере показывает замок, отправка сообщений не страдает.
- **Второй порт для документов** — `FileSummaryProvider`
  (`summarize(DocumentText, locale, min, max): FileSummaryResult`), отдельный
  от правки текста: у файла свои пределы, своя валидация и свой промпт.
  Реализации — `PolzaFileSummaryProvider`, `NullFileSummaryProvider`,
  `FakeFileSummaryProvider`. Наружу уходит только извлечённый текст документа:
  разбор PDF/DOCX/TXT выполняет `DocumentTextExtractor` внутри установки.
- **Асинхронность для документов**: пересказ идёт заданием очереди `ai`
  (отдельная группа Horizon), ход и результат — событием
  `ai.file_summary.updated.v1` на личный канал автора запроса, состояние
  всегда подтверждается запросом. Черновик виден только запросившему и
  публикуется обычным сообщением от его имени лишь по подтверждению
  (`docs/features/ai-file-summary.md`).
- **CI**: обычный прогон использует фейкового поставщика; проверка против
  настоящего Polza — `./tools/chat smoke polza`, включается только при
  заданном `AI_API_KEY`.

## Альтернативы

- **SDK поставщика в Application-слое** — отвергнуто: домен привязывается к
  формату конкретного сервиса, смена поставщика становится переписыванием.
- **Отправка последних сообщений комнаты для контекста** — отвергнуто по
  умолчанию: инструкция требует не отправлять историю, когда операции хватает
  одного текста. Возврат к этому потребует явного согласия пользователя.
- **Хранение промптов и ответов для отладки** — отвергнуто: это приватная
  переписка. При необходимости включается отдельным решением с ретенцией.
- **Асинхронная обработка через очередь** — отвергнута для правки черновика:
  ожидание короткое, клиент умеет отменять; очередь усложнила бы возврат
  результата. Для пересказа документа решение обратное: чтение файла и ответ
  поставщика идут десятки секунд, поэтому там очередь обязательна.
- **Единый `TextRevisionProvider` с флагом режима для файлов** — отвергнуто:
  контракты и пути валидации разные, флаг сделал бы оба нечитаемыми.

## Последствия

- Каталог `src/Infrastructure/Providers/` — единственное место, знающее про
  конкретного поставщика; добавление второго не затрагивает домен.
- Скилл `polza-ai` предписывает размещать клиент в
  `app/Infrastructure/Services/AI/` — здесь применяется раскладка
  `STRUCTURE.md` (пакет `packages/backend/ai`), она главнее (CLAUDE.md, §4).
- Стоимость наблюдаема: цены за 1000 токенов задаются конфигурацией, расход
  пишется в аудит.

## Критерии пересмотра

- Потребность в контексте беседы для качества ответа (нужен явный опт-ин).
- Появление второго поставщика или локальной модели.
- Требование хранить полные промпты для расследований (нужна политика ретенции).
