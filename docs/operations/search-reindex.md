# Поиск: включение и переиндексация

## Включение

1. Задайте `TYPESENSE_API_KEY` в `.env` (стойкий ключ, не значение по умолчанию).
2. Поставьте `SEARCH_ENABLED=true`.
3. Поднимите сервис: он уже описан в `compose.prod.yaml` (`typesense`).
4. Постройте индекс: `docker compose exec api php artisan chat:search-reindex --fresh`.

Пустое обязательное значение при включённом поиске — ошибка запуска, а не тихо
неработающий индекс: приложение сообщит, какого ключа не хватает (`host`,
`api_key`, `port`, `collection`), не показывая самого значения.

## В локальном стеке

`./tools/chat up` поднимает Typesense и включает поиск сам: коллекция
создаётся при старте, worker слушает очередь `search`, поэтому новые
сообщения индексируются на лету. Проверить целиком —
`./tools/chat smoke search`.

## Переиндексация

```bash
php artisan chat:search-reindex          # догрузить существующую коллекцию
php artisan chat:search-reindex --fresh  # пересоздать коллекцию с нуля
php artisan chat:search-reindex --chunk=1000
```

Команда читает PostgreSQL — источник истины — порциями по `id`, пропуская
системные записи и мягко удалённые сообщения. Её безопасно запускать повторно:
документы перезаписываются, дублей не возникает.

Переиндексация нужна после включения поиска, восстановления базы из резервной
копии, потери тома `typesense-data` и при подозрении на расхождение.

## Резервные копии

Том `typesense-data` копировать не обязательно: индекс восстановим командой
выше. Обязательна резервная копия PostgreSQL.

## Если поиск недоступен

API отвечает `503` с кодом `service_unavailable`, интерфейс показывает
«поиск сейчас недоступен», а отправка, чтение и real-time чата продолжают
работать. Проверьте контейнер `typesense`, затем `./tools/chat smoke search`.
