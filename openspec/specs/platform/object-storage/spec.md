## Purpose

Где продукт хранит файлы, кто их выдаёт и по каким общим правилам готовятся
производные изображения для всех функций, которые с файлами работают.

## Requirements

### Requirement: Файлы продукта хранятся в объектном хранилище

Все файлы, которые загружают люди, SHALL храниться в объектном хранилище
установки — в бакете `chat`. Локальный диск приложения SHALL использоваться
только для временных файлов обработки и НЕ SHALL быть местом постоянного
хранения.

Каждый вид медиа SHALL занимать собственный префикс внутри бакета, чтобы
назначение файла было видно по его пути.

#### Scenario: Загруженный файл попал в хранилище

- **WHEN** приложение принимает файл от человека
- **THEN** файл оказывается в объектном хранилище под префиксом своего вида,
  а в базе остаются только сведения о нём

#### Scenario: Локальный диск не копит загруженное

- **WHEN** обработка файла завершилась
- **THEN** на локальном диске приложения его не остаётся

#### Scenario: Хранилище недоступно

- **WHEN** хранилище не отвечает
- **THEN** операция с файлом завершается понятной ошибкой, а части продукта,
  не связанные с файлами, продолжают работать

### Requirement: Хранилище закрыто, файлы выдаёт приложение

Бакет SHALL быть закрытым: анонимное чтение объектов разрешено быть НЕ SHALL.
Файл SHALL выдаваться только через приложение, которое проверяет право на него
по правилам той функции, которой файл принадлежит.

Ответ с файлом SHALL отдаваться так, чтобы браузер не исполнял и не отрисовывал
его содержимое как страницу.

#### Scenario: Обращение в обход приложения

- **WHEN** кто-то обращается к объекту хранилища напрямую
- **THEN** файл не отдаётся

#### Scenario: Право проверяет владеющая функция

- **WHEN** приложение отдаёт файл
- **THEN** право на него проверено правилами той функции, которой файл
  принадлежит, а не самим фактом знания адреса

#### Scenario: Содержимое не исполняется браузером

- **WHEN** человек открывает выданный файл
- **THEN** браузер не отрисовывает его как страницу приложения

### Requirement: Производные изображения хранятся в webp

Любое подготовленное приложением изображение — миниатюра, уменьшенная копия,
подогнанный размер — SHALL храниться в формате webp.

Исходный файл SHALL сохраняться там, где человек может захотеть получить
обратно именно присланное. Для оформительских изображений, которые никто не
скачивает, исходник храниться НЕ SHALL.

Производные изображения SHALL готовиться в очереди, отдельной от живой
переписки, и НЕ SHALL задерживать основной сценарий.

#### Scenario: Миниатюра готова

- **WHEN** изображение принято и его производная подготовлена
- **THEN** производная лежит в webp

#### Scenario: Производная ещё готовится

- **WHEN** изображение только что принято
- **THEN** основной сценарий уже завершён, а места, где нужна производная,
  показывают состояние ожидания

#### Scenario: Изображение не удалось обработать

- **WHEN** подготовить производную не получилось
- **THEN** это видно в журнале, повтор ограничен, а исходная операция не
  считается неудавшейся задним числом

### Requirement: Файлы уходят вместе с тем, чему принадлежат

Удаление объекта, которому принадлежит файл, SHALL удалять из хранилища и сам
файл, и все его производные. Осиротевшие файлы SHALL быть выявляемы и
удаляемы, а не копиться молча.

#### Scenario: Владелец файла удалён

- **WHEN** удаляется то, чему принадлежал файл
- **THEN** файл и его производные удаляются из хранилища

#### Scenario: Хранилище недоступно в момент удаления

- **WHEN** удаление происходит, а хранилище временно не отвечает
- **THEN** основная операция доводится до конца, а очистка повторяется позже
  и не теряется молча
