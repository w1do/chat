## Context

Мотивация — в `proposal.md`. Ниже то, что определяет подход; проверено по коду.

- Оболочка в `apps/chat-web/src/pages/ChatPage.tsx` занимает ровно видимую
  область: `position: fixed`, `height` из `visualViewport.height`,
  `transform: translateY(offsetTop)`.
- Числа даёт `useKeyboardInsets` в `packages/frontend/ui`. Клавиатура
  вычисляется как `innerHeight − height − offsetTop` с порогом 120 px;
  масштаб страницы там не учитывается вовсе.
- Слушаются только `resize` и `scroll` визуального вьюпорта плюс `resize`
  окна. Событий о возврате из фона (`visibilitychange`, `pageshow`) нет.
- В `index.html` мета-вьюпорт задаёт `initial-scale=1` и
  `interactive-widget=resizes-content`; ограничений масштаба нет.
- `touch-action` в исходных стилях не задан нигде: в собранном CSS есть
  только переменные Tailwind, самого правила нет.
- В `global.css` уже есть `.no-select` с `-webkit-touch-callout` — место, где
  живут правила поведения касаний, известно.

Ключевая связь двух симптомов: при увеличении визуальный вьюпорт уменьшается и
получает ненулевой `offsetTop`. Формула клавиатуры даёт больше порога,
оболочка сжимается и сдвигается — панель ввода оказывается посреди экрана.
То есть «улетевшая клавиатура» это не отдельная поломка, а следствие того, что
масштаб не отличают от клавиатуры.

## Goals / Non-Goals

**Goals:**

- Случайный жест не меняет масштаб приложения.
- Оболочка остаётся правильной при любом масштабе, включая заданный человеком
  осознанно.
- После возврата из фона раскладка восстанавливается сама.

**Non-Goals:**

- Не запрещается увеличение как таковое: доступность (WCAG 2.2 AA, 1.4.4)
  остаётся, запрет касается только жестов.
- Не трогаются настольные браузеры: `Ctrl` с колесом и `Ctrl` с «+/−»
  работают по-прежнему.
- Не меняется собственная настройка размера текста (`TEXT_SIZE_PX`) и не
  добавляется новая настройка увеличения.
- Не меняется способ измерения клавиатуры и порог 120 px — правится только
  то, что портит измерение.

## Decisions

### 1. Мета-вьюпорт не трогаем

`user-scalable=no` и `maximum-scale=1` не добавляются. Они запрещают не жест,
а само увеличение, и нарушают критерий 1.4.4 — заявленный в `CLAUDE.md` §3.
Вдобавок толку от них немного: iOS Safari с 10-й версии их игнорирует, а
Android перекрывает системной настройкой принудительного увеличения. Жест
всё равно пришлось бы закрывать другим способом — им и ограничиваемся.

Альтернатива (полный запрет через мету) обсуждалась и отклонена сознательно:
она стоит соответствия доступности, а обещанного результата на iOS не даёт.

### 2. Жест закрывается двумя средствами: CSS и события iOS

`touch-action` на корне оболочки задаётся как `pan-x pan-y` — прокрутка
остаётся, `pinch-zoom` и двойной тап из набора разрешённых жестов уходят.
Именно `pan-x pan-y`, а не `manipulation`: `manipulation` это
`pan-x pan-y pinch-zoom`, то есть щипок он как раз разрешает и убирает только
двойной тап.

Этого достаточно для Chrome на Android. Safari на iOS `touch-action` для
масштаба страницы не слушает, поэтому дополнительно подавляются
`gesturestart`/`gesturechange`/`gestureend` — нестандартные события, которыми
Safari сообщает о щипке. Слушатели ставятся на документ один раз при запуске
приложения, `passive: false` обязателен: иначе отмена не сработает.

Оба средства нужны вместе, и ни одно не является запасным для другого: они
закрывают разные браузеры.

Правило `touch-action` вешается на корень оболочки, а не на `html`/`body`:
так запрет виден там же, где оболочка задаёт себе геометрию, и не мешает
служебным страницам вроде экрана приглашения.

### 3. Масштаб отличается от клавиатуры по `visualViewport.scale`

Пока `scale` заметно больше единицы, приложение не считает уменьшение видимой
области клавиатурой и не сдвигает оболочку: `keyboard` даёт ноль, `offsetTop`
не применяется. Высота при этом берётся прежним способом — оболочка обязана
оставаться в видимой области, просто перестаёт трактовать масштаб как
клавиатуру.

Сравнение с единицей — с допуском: браузеры отдают дробные значения вроде
`1.0000001`, и строгое равенство давало бы ложные срабатывания.

Альтернатива — «раз жесты запрещены, масштаб всегда 1» — не годится: мы
намеренно оставили увеличение из меню браузера и системную настройку, и
именно в этих режимах перекос был бы виден.

### 4. Перемер при возврате: событие плюс отложенный повтор

К существующим слушателям добавляются `visibilitychange` документа и
`pageshow` окна. Одного события мало: на момент разворачивания браузер ещё
двигает системные панели и клавиатуру, и снятые сразу числа успевают
устареть. Поэтому измерение повторяется ещё раз после того, как браузер
отрисует кадр, — так фиксируется уже устоявшаяся геометрия.

Альтернатива — опрашивать геометрию по таймеру — отклонена: постоянная работа
в фоне ради редкого события, и всё равно без гарантии попасть в момент
устаканивания.

Состояние обновляется, только если числа действительно изменились: лишний
рендер оболочки на каждом переключении вкладки не нужен.

### 5. Хук остаётся единственным источником геометрии

Ни оболочка, ни экраны не начинают читать `visualViewport` сами. Всё, что
знает о масштабе и возврате из фона, живёт в `useKeyboardInsets`, и оболочка
получает уже пригодные числа. Так поведение проверяется одним набором тестов
хука, а не по всем экранам.

## Risks / Trade-offs

- [Человек лишается быстрого увеличения щипком — например, чтобы рассмотреть
  мелкий текст] → увеличение остаётся в меню браузера и в системной
  настройке, а размер текста приложения меняется в его собственных
  настройках; именно эта пара и закрывает потребность, ради которой жест
  использовали.
- [`touch-action: pan-x pan-y` запрещает и вращение двумя пальцами, которого в
  продукте нет] → потери нет: жест не используется ни на одном экране.
- [Подавление `gesturestart` — нестандартное API только для Safari] → в
  остальных браузерах события не приходят вовсе, слушатель молчит; ветвления
  по user-agent не требуется.
- [Порог по `scale` может не сработать на браузере, который не отдаёт
  `scale`] → тогда поведение остаётся сегодняшним, не хуже; в таких браузерах
  жест уже закрыт средствами из решения 2.
- [Повторное измерение после кадра может прийти, когда экран уже уходит в
  фон] → сравнение с прежними числами не даст лишнего рендера, а следующее
  разворачивание перемерит заново.

## Migration Plan

Изменение целиком клиентское: правится один хук, добавляется правило стилей и
подписка на события в оболочке. Схема базы, API и контракты событий не
затрагиваются. Выкладка обычной пересборкой фронтенда, откат — возврат
образа.
