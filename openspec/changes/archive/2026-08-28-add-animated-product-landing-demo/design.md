## Context

См. мотивацию в `proposal.md` и поведение в
`specs/presentation/product-landing-demo/spec.md`.

В корне репозитория сейчас нет демонстрационного лендинга. Рабочий интерфейс
собирается как React-приложение, но презентационный артефакт должен открываться
самостоятельно и не входить в composition root. `AGENTS.md` и `CLAUDE.md`
сейчас побайтово идентичны; это свойство нужно сохранить.

Источником продуктовых утверждений остаётся текущее состояние репозитория. На
момент предложения подтверждены auth/profile, комнаты и роли, сообщения,
realtime/presence, приглашения, guest flow, вложения и изображения,
offline/database/email/Web Push уведомления, PWA, поиск, AI-revision,
администрирование и self-hosted runtime. Незавершённые direct messages и
NativePHP-клиент не входят в демонстрацию как готовые функции. Перед
реализацией этот snapshot необходимо повторно сверить.

GSAP документирует отдельное подключение и регистрацию ScrollTrigger, а Motion
предоставляет browser-friendly `animate`/`inView`. Обе зависимости меняются
независимо, поэтому конкретные стабильные версии проверяются перед реализацией
и фиксируются в URL, без `latest`.

## Goals / Non-Goals

**Goals:**

- получить режиссируемую презентацию, которая убедительно выглядит в записи
  16:9 и остаётся полноценной responsive-страницей;
- сделать исходник понятным для точечных обновлений без сборщика;
- отделить декоративные сцены от рабочего продукта и любых реальных данных;
- обеспечить статичный, keyboard-friendly и reduced-motion режимы;
- сделать claims прослеживаемыми до текущей документации и тестов.

**Non-Goals:**

- перенос лендинга внутрь `apps/chat-web` или замена интерфейса чата;
- создание production-маркетингового сайта, SEO-контура или CMS;
- подключение аналитики, формы лида, backend API или WebSocket;
- рендеринг самого YouTube-видео, запись голоса и монтаж;
- демонстрация незавершённых roadmap-функций;
- отдельный asset pipeline, framework или runtime package для лендинга.

## Decisions

### 1. Один авторский файл с progressive enhancement

`/demo.html` содержит semantic HTML, CSS, JS, mockup-данные и inline SVG.
Локальных картинок, CSS и JS рядом не будет. GSAP, ScrollTrigger и Motion
подключаются из общедоступного CDN по зафиксированным версиям; системные font
stacks являются обязательным fallback, а внешний display/mono font — только
необязательным улучшением.

Содержание видимо до запуска JS. Скрипт добавляет анимации через `from`/runtime
initial states, а не оставляет важные блоки скрытыми в базовом CSS. Ошибка CDN
поэтому выключает эффект, но не страницу.

Альтернатива — встроить минифицированные копии библиотек внутрь HTML. Она дала
бы полностью offline-анимацию, но резко увеличила бы файл, усложнила аудит
лицензий и обновления. Альтернатива с Vite/React отвергнута, потому что нарушает
требование открыть единственный файл без сборки.

### 2. Пятнадцать секций как сценарий, а не каталог карточек

Стабильные якоря и драматургия:

1. `hero` — тезис «свой мессенджер на своём сервере» и главный product mockup;
2. `ownership` — данные, отсутствие telemetry/control plane, открытый код;
3. `interface` — мобильный и desktop shell, темы и доступность;
4. `rooms` — public/private комнаты, роли и управление участниками;
5. `messages` — replies, reactions, mentions, edit/delete и жесты;
6. `realtime` — Reverb, typing, presence и HTTP resync;
7. `invites` — ссылки, guest account и безопасный token flow;
8. `media` — вложения, галерея, аватары, room image и wallpaper;
9. `notifications` — «только когда вас нет», grouping, PWA и Web Push;
10. `search` — Typesense с обязательной PostgreSQL-проверкой доступа;
11. `ai` — безопасное предложение правки черновика, а не автопубликация;
12. `control` — admin status, AI switch, audit и privacy boundaries;
13. `architecture` — Laravel/React/Reverb/Redis/PostgreSQL/Typesense в одном
    self-hosted контуре;
14. `install` — документированная команда и симуляция старта сервисов;
15. `cta` — открытый код и приглашение развернуть собственный экземпляр.

Каждый блок получает один главный визуальный образ: mock chat, presence
constellation, invite token, notification stack, search beam, AI diff,
architecture map или terminal. Это делает запись разнообразной и не превращает
страницу в повторяющуюся сетку одинаковых feature cards.

### 3. Макро- и микроанимации принадлежат разным движкам

- GSAP + ScrollTrigger: hero timeline, последовательное раскрытие крупных сцен,
  scrub для архитектурных линий и очень ограниченный pinning только там, где он
  помогает объяснению.
- Motion: `inView`-появления небольших chips/cards, spring feedback кнопки
  копирования и локальные состояния terminal/notification mockup.
- Один DOM-узел не получает от обоих движков конкурирующие `transform` или
  `opacity`. При необходимости используются wrapper и child с разной
  ответственностью.
- Нативная прокрутка сохраняется; smooth-scroll hijacking не используется.

При `prefers-reduced-motion: reduce` анимационные setup-функции не запускаются,
ScrollTrigger не регистрируется для сцен, а CSS отключает transition/animation.
Контент уже находится в финальном состоянии.

Альтернатива с одним GSAP проще по зависимостям, но не выполняет прямое
требование использовать Motion. Равноправное смешивание движков отвергнуто из-за
конфликтов transform и сложной отладки.

### 4. Визуальная система задаётся токенами внутри CSS

CSS custom properties определяют почти чёрный canvas, плотные тёмные панели,
приглушённый текст, белый основной текст, cyan/violet/lime акценты, компактные
радиусы, жёсткие границы, сдержанные тени и spacing. Display stack остаётся
геометрическим, code stack — `JetBrains Mono`, `Cascadia Code`,
`SFMono-Regular`, `ui-monospace` с корректным fallback.

Фоновая фактура ограничивается редкими scanline-полосами, единичными
техническими линиями и локальными radial glow. Двойная координатная сетка,
постоянный клетчатый фон и повторяющийся каталог одинаковых карточек не
используются: code/cyberpunk-характер создаётся типографикой, контрастом,
асимметричными композициями и точечными световыми акцентами. Панели и controls
используют малые радиусы; pill-форма остаётся только там, где она сообщает
конкретный компактный статус, а не применяется как общий декоративный стиль.
Декоративные линии и glow не уменьшают контраст текста.

Размеры строятся через `clamp()`, layout — через CSS Grid/Flex, а брейкпоинты
ориентируются на содержимое. Inline SVG и CSS shapes заменяют тяжёлые растровые
скриншоты. На широкой записи основной контент держится в safe-area; на 360 px
всё становится одной колонкой.

### 5. Контент хранит связь с доказательствами

В начале `../../../demo__4.html` будет короткий maintenance-комментарий с датой сверки и
источниками, а секции получат читаемые comments/data-атрибуты с соответствующим
feature domain. Перед написанием текста исполнитель повторно читает
`SUMMARY.md`, README и релевантные `docs/features/*`; статус одного OpenSpec
change сам по себе не считается доказательством.

Продуктовый текст использует конкретное поведение, но избегает неподтверждённых
цифр, benchmark, SLA, гарантий безопасности и сравнений с конкурентами. Direct
messages и NativePHP появляются только после отдельной завершённой реализации и
синхронизации landing.

### 6. Терминал интерактивен, но не исполняем

Команда берётся без смысловых правок из VPS quick start в README. Кнопка
использует Clipboard API и fallback через временное выделение текста для
ограниченного `file://`-контекста; live-region сообщает «Скопировано» или даёт
понятную инструкцию скопировать вручную. «Выполнение» — только таймер появления
заранее заданных безопасных строк.

Никаких `eval`, shell bridge, fetch к продукту, реальных hostnames/credentials
или скрытых форм нет.

### 7. Проверка сочетает структурные assertions и визуальный просмотр

Playwright smoke открывает страницу через локальный static server и проверяет:
15 секций/уникальные IDs, доступность основных controls, копирование команды,
отсутствие горизонтального overflow на 390×844 и 1440×900, reduced-motion,
статичность при заблокированных внешних ресурсах и отсутствие запросов к
`/api`, WebSocket или неизвестным origins. Проверка с отключённым JS
подтверждает доступность содержания.

Для итоговой приёмки снимаются full-page и ключевые viewport screenshots в
desktop/mobile/reduced-motion. Визуальный просмотр обязателен: build или
структурный тест не доказывает качество композиции и анимационного темпа.
Runtime-тесты основного чата не нужны, потому что его код не меняется.

### 8. Правило обновления входит в docs workflow и Definition of Done

Одинаковый текст добавляется в `AGENTS.md` и `CLAUDE.md` рядом с правилами
документации/реализации: каждый новый или заметно изменённый пользовательский
feature обновляет существующую сцену или добавляет новую в `../../../demo__4.html` в том же
изменении. Лендинг обновляется только после появления доказательств
implementation; planned wording не маскируется под доступную возможность.

Definition of Done отдельно проверяет актуальность landing для затронутой
функции. После правки выполняется сравнение двух instruction-файлов.

## Risks / Trade-offs

- [CDN недоступен во время записи] → базовый документ полностью видим, версии
  зафиксированы, перед записью выполняется offline/failure smoke.
- [GSAP и Motion конфликтуют] → жёстко разделить macro/micro targets и свойства,
  использовать wrapper/child и проверять console errors.
- [Анимация дёргается на слабом устройстве] → преимущественно transform/opacity,
  ограничить blur, particles и pinning, не перехватывать native scroll.
- [Маркетинговый текст обгоняет код] → evidence map, запрет claims для
  planned/in-progress и обязательное правило в двух instruction-файлах.
- [Один файл становится трудно сопровождать] → явные HTML/CSS/JS секции,
  стабильные IDs, токены и короткие функции; без base64-видео и тяжёлых bitmap.
- [Clipboard запрещён для `file://`] → fallback с выделением команды и ясным
  live-region сообщением вместо ложного успеха.
- [Видео хорошо, мобильный web плохо] → отдельные viewport checks и запрет
  фиксированной canvas-ширины.
- [Cyberpunk-декор превращается в визуальный шум] → ограничить scanline и glow
  фоном/акцентными зонами, не использовать двойную сетку, pill-heavy controls и
  повторяющиеся карточные матрицы; проверять иерархию по desktop/mobile
  screenshots.
- [Сторонние запросы противоречат образу self-hosted] → никаких analytics и
  продуктовых API; CDN используется только самим демонстрационным HTML и имеет
  статический fallback.

## Migration Plan

1. Повторно сверить реализованные возможности и команду установки.
2. Добавить `../../../demo__4.html` как независимый статический артефакт.
3. Добавить одинаковое правило синхронизации в `AGENTS.md` и `CLAUDE.md`.
4. Выполнить структурную, accessibility, responsive, reduced-motion,
   offline-fallback и визуальную проверку.
5. Убедиться, что основной build/маршруты приложения не изменились.

Изменение аддитивное и не требует data/API migration. Rollback состоит из
удаления `../../../demo__4.html` и двух синхронно добавленных правил; runtime чата остаётся
неизменным.
