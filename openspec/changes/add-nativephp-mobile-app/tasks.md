## 1. Зафиксировать prerequisites и архитектурные границы

- [ ] 1.1 Проверить в чистом credentialed-окружении совместимость выбранных версий Laravel, PHP, Node/Vite, `nativephp/mobile` 4.x, `nativephp/mobile-firebase` и `nativephp/mobile-secure-storage`, зафиксировать точные ограничения и источники пакетов; проверка: `composer show`, `composer why-not` и пробная установка завершаются без изменения production-приложения и без попадания credentials в Git.
- [ ] 1.2 Добавить ADR о выделенном `apps/chat-mobile`, PHP-mode WebView, мобильных Sanctum-сессиях, FCM/APNs и модели «одна self-hosted установка — одна сборка», согласовав его с ADR-005; проверка: ссылки из ADR разрешаются, а архитектурная проверка не обнаруживает зависимости мобильного приложения от внутренних классов backend-пакетов.
- [ ] 1.3 Описать публичные параметры мобильной сборки, секретные файлы Firebase/signing и правила `.gitignore`, включая запрет backend-секретов в bundle; проверка: preflight принимает полный безопасный пример конфигурации и отклоняет отсутствующие, wildcard- и небезопасные значения.
- [ ] 1.4 Добавить каркас команд `./tools/chat mobile ...` для install, preflight, test, run, build, package и verify без выполнения публикации; проверка: `./tools/chat mobile --help` документирует все команды и возвращает ненулевой код для неизвестной команды.

## 2. Реализовать серверные мобильные сессии

- [ ] 2.1 Добавить в identity-пакет типизированные `spatie/laravel-data` DTO и contracts для mobile register/login/refresh/logout, не экспортируя инфраструктурные модели; проверка: package-тесты сериализации, валидации и публичного API DTO проходят.
- [ ] 2.2 Добавить принадлежащую identity-пакету forward-only миграцию `mobile_sessions`, модель и ограничения для пользователя, installation ID, Sanctum access token, hash refresh token, срока, rotation и revoke; проверка: миграционные тесты проходят на чистой БД и при обновлении существующей схемы, а rollback не затрагивает web-сессии.
- [ ] 2.3 Реализовать команды и handlers регистрации и входа, которые создают ограниченный ability `mobile`, короткоживущий access token и refresh token с серверным hash; проверка: feature-тесты покрывают успешные ответы, неверные credentials, validation envelope, rate limit и границы access/refresh TTL.
- [ ] 2.4 Реализовать атомарную rotation refresh token с блокировкой строки, constant-time сравнением и отзывом семейства при replay; проверка: тесты последовательного refresh, повторного token replay и конкурентных запросов доказывают выдачу не более одной валидной следующей пары.
- [ ] 2.5 Реализовать идемпотентный mobile logout, отзыв сессий при смене/сбросе пароля и административном security revoke, публикуя application events после commit; проверка: feature- и integration-тесты подтверждают отзыв access/refresh token и отсутствие влияния на чужие и web-сессии.
- [ ] 2.6 Добавить тонкие mobile auth controllers/routes `/api/v1/auth/mobile/*`, Data requests/resources и единый JSON error envelope; проверка: каждый endpoint имеет policy/rate-limit/feature-тест и не содержит `$request->validate()`, `$request->all()` или ручной сборки response-массивов.
- [ ] 2.7 Описать mobile auth endpoints и security schemes в OpenAPI 3.1 и перегенерировать TypeScript client; проверка: OpenAPI validation и contract-тесты проходят, а повторная генерация клиента не создаёт diff.
- [ ] 2.8 Добавить bearer-вариант `/api/v1/broadcasting/auth` с теми же channel policies, сохранив существующий cookie/CSRF маршрут для PWA; проверка: integration-тесты разрешают приватный канал только участнику комнаты как для cookie, так и для Bearer, и отклоняют отозванный token.

## 3. Добавить серверный transport нативных push-уведомлений

- [ ] 3.1 Добавить в notifications-пакет миграцию и модель `native_push_devices` с user ID, installation ID, platform, зашифрованным token, уникальным token hash, версиями приложения и состоянием disable; проверка: миграционные и model-тесты подтверждают уникальность, encryption-at-rest и безопасную сериализацию без token.
- [ ] 3.2 Добавить Data, commands/handlers и тонкие endpoints `PUT|DELETE /api/v1/native-push/devices/{installationId}` для идемпотентной регистрации, rotation и удаления токена; проверка: feature-тесты покрывают повторную регистрацию, смену пользователя/token, authorization, validation и rate limit.
- [ ] 3.3 Связать отзыв mobile session с деактивацией её native push registration через composition-root orchestration, не читая таблицы identity из notifications-пакета; проверка: integration-тесты logout, password reset и security revoke отключают только связанные installations.
- [ ] 3.4 Ввести `NativePushSender` contract и FCM HTTP v1 infrastructure adapter с server-only service account, Redis-кешем OAuth access token, timeout, retries и нормализованными ошибками; проверка: fake HTTP-тесты покрывают success, auth refresh, 429/5xx, permanent invalid-token и отсутствие сетевых вызовов в обычном CI.
- [ ] 3.5 Разделить доставку логического канала `push` на независимые идемпотентные Web Push и Native Push jobs после commit, сохранив пользовательскую настройку и правила присутствия; проверка: queue-тесты доказывают, что сбой одного transport не блокирует второй и retry не создаёт дубликат другого transport.
- [ ] 3.6 Добавить общий privacy-safe formatter native payload с versioned deep link, collapse key, badge и локализуемым title/body без текста приватного сообщения по умолчанию; проверка: unit-тесты snapshot-полезной нагрузки не содержат message body, access token, email или server secret.
- [ ] 3.7 Реализовать обработку canonical token/invalid token, backoff, bounded retries, timeout и `failed()` audit для native push job; проверка: job-тесты подтверждают rotation token, disable permanent invalid token и отсутствие disable при временной ошибке.
- [ ] 3.8 Добавить безопасную диагностическую команду отправки native push конкретному installation, выключенную без явного флага окружения; проверка: command-тесты подтверждают permission/config guard, redaction token и dry-run без обращения к FCM.
- [ ] 3.9 Обновить OpenAPI, сгенерированный клиент и feature-документацию для native push endpoints; проверка: OpenAPI/contract/doc checks проходят, а повторная генерация клиента не создаёт diff.
