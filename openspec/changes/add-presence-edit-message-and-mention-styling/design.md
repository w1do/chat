# Technical Design: Presence & Last Seen, Message Editing, and Mention Autocomplete

## Context

См. `proposal.md` для описания мотивации и продуктовых требований.
Текущий стек:
- Backend: Laravel 13, PostgreSQL, Redis, Laravel Reverb (WebSocket), Spatie DTOs/Data, DDD + CQRS-lite.
- Frontend: React 19, TypeScript, TanStack Query, Laravel Echo / Reverb, Tailwind CSS.

## Goals / Non-Goals

**Goals:**
- Точное и масштабируемое отслеживание присутствия пользователя онлайн и времени последней активности (`last_seen_at`) без лишней нагрузки на БД.
- Полноценный UX редактирования сообщений (меню действий -> режим правки в строке ввода -> API -> real-time трансляция `message.updated.v1` -> бейдж `(отредактировано)`).
- Элегантный интерфейс автодополнения упоминаний (`@`) с подсветкой аватарок, статусов, никнеймов и полной поддержкой клавиатурной навигации (`Up`/`Down`/`Enter`/`Tab`/`Escape`).
- Выделение упоминаний в теле сообщений и специальный акцент на сообщениях, в которых тегнут текущий пользователь.

**Non-Goals:**
- Полноэкранная история версий правок сообщения в MVP (хранится только факт изменения и время `edited_at`).
- Сложный WYSIWYG/Rich-Text редактор (сохраняется простой и быстрый текстовый ввод Markdown).

## Decisions

### 1. Отслеживание присутствия и `last_seen_at`
- **Решение**: Добавить поле `last_seen_at` (timestamp, nullable) в таблицу `users`.
- **Оптимизация нагрузки**: При высокой частоте запросов и ping-событий отслеживание кэшируется в Redis со скользящим окном (троттлинг записи в БД 1 раз в 60 секунд на пользователя), а также обновляется при явных мутациях (отправка сообщения, отметка прочитанности).
- **Синхронизация**: Присутствие в комнате и личных диалогах отслеживается через Echo Presence Channel (`chat.room.{id}` / `presence-chat`) и сопоставляется со списком участников.
- **Форматирование времени**: На клиенте внедряется локализованный хелпер `formatLastSeen(date, now)` («только что», «N мин назад», «сегодня в HH:MM», «вчера в HH:MM», «D MMM в HH:MM»).

### 2. Редактирование сообщений (UX & Realtime)
- **Решение**: 
  - В `MessageActionsSheet` добавляется пункт «Редактировать» (только для собственных текстовых сообщений).
  - При выборе поле ввода `ChatScreen` переключается в `editingMessage` режим: над строкой ввода появляется плашка с индикатором редактируемого сообщения и кнопкой отмены, а текст сообщения подставляется в инпут.
  - Сохранение выполняется через `useEditMessage` (`PATCH /api/v1/messages/{message}`).
  - Бэкенд валидирует автора через Policy (`Gate::authorize('update', $message)`), сохраняет изменения, выставляет `edited_at = now()` и транслирует `MessageUpdatedV1`.
  - В `MessageBubble` добавляется метка `(отредактировано)`.

### 3. Rich Mention Autocomplete & Styling
- **Решение**:
  - Компонент `MentionPicker.tsx` преобразуется в стилизованный плавающий дропдаун над строкой ввода.
  - Каждая строка кандидата включает:
    - Аватарку пользователя с цветным кольцом/свечением при активности и индикатором онлайн/оффлайн.
    - Никнейм (`@username`) с полужирным начертанием и подсветкой совпадений.
    - Отображаемое имя (Full Name).
  - Управление с клавиатуры: перехват `keydown` в `textarea` для клавиш `ArrowUp`, `ArrowDown`, `Enter`, `Tab`, `Escape`.
  - При выборе тег `@username ` вставляется на место курсора с сохранением окружающего текста.

### 4. Подсветка упоминаний в ленте
- **Решение**:
  - В `MessageBubble` текст парсится на упоминания `@username`: они оборачиваются в акцентные бейджи `<span className="mention-badge">@username</span>`.
  - Если список `message.mentions` содержит ID текущего авторизованного пользователя, пузырь сообщения получает лёгкий акцентный бордер/фон подсветки.

## Risks / Trade-offs

- **[Риск] Высокая нагрузка на базу данных при обновлении `last_seen_at`**  
  → *Митигация*: Троттлинг обновлений через Redis cache key `user:{id}:last_seen_throttled` с TTL 60 секунд.
- **[Риск] Конфликт клавиатурных событий в поле ввода (перевод строки vs выбор упоминания)**  
  → *Митигация*: При открытом `MentionPicker` клавиши `Enter` и `Tab` перехватываются (`e.preventDefault()`) для подтверждения выбора, а обычный `Enter` без открытого дропдауна отправляет сообщение (или делает перенос при `Shift+Enter`).
- **[Риск] Смещение позиции курсора при вставке ника**  
  → *Митигация*: Корректный расчёт `selectionStart`/`selectionEnd` с вызовом `textarea.setSelectionRange(...)` после вставки.

## Migration Plan

1. Выполнить миграцию БД для добавления `last_seen_at` в таблицу `users`.
2. Обновить API ресурсы пользователей и участников комнат.
3. Добавить UI компоненты и протестировать на чистом клиенте и в Jest/Vitest suite.
